Paper2Alpha — Technical Reference Sheet

Code-grounded summary for interview preparation  |  Generated 2026-06-18

1. Goal

A quant research workbench that operates in two modes:

  • Claude desktop (MCP mode): Claude calls 10 exposed tools autonomously to search arXiv, download papers, build semantic indexes, and analyze paper content — functioning as a research agent.
  • Web dashboard (browser mode): A Next.js + FastAPI web app where a researcher browses a local paper library, downloads papers, selects one, and asks questions in an LLM chat panel with a structured analysis prompt.
There is no automated paper→alpha pipeline yet. No code automatically extracts trading signals from papers or calls the quant model from the dashboard.

LLM agent role — MCP mode (agentic)

Research_LLM/mcp_server.py is built on FastMCP. Claude desktop calls the tools in an autonomous loop: search arXiv → download → build index → read/analyze paper → generate output. This is genuine agentic behavior with real tool use.

LLM agent role — chat panel (non-agentic)

The dashboard chat is not agentic. It is a pure text generator. The selected paper is injected into the system prompt; the LLM generates a response but calls no tools and makes no decisions.

3. Data & Features — What Is Actually Implemented

Confirmed real and fully functional

  • arXiv paper search, download (HTML→Markdown via markdownify, PDF via pypdf), local storage by category
  • Metadata persistence (metadata.json), batched arXiv API calls with rate limiting and exponential-backoff retry
  • Abstract-level and section-level semantic search via ChromaDB (BAAI/bge-base-en-v1.5)
  • SSE-streaming download + auto-index pipeline (metadata → abstract embedding → section embedding)
  • LLM chat with multi-provider support (Claude, Ollama, OpenRouter free models), temperature=0.3 default
  • Task-mode structured prompt injection (paper_analysis.md): Branch A (alpha/strategy) vs Branch B (general), with enforced section output format
  • Path traversal protection on all local file reads

4. Models / Major Components

IrrationalityIndex (Quant Models/Irrationality_Index/Index_Model.py)

A Keras/TensorFlow transformer model producing a 0–100 score per time step.

  • TransformerEncoderBlock: Multi-head attention + LayerNorm + 2-layer FFN + Dropout (rate 0.1). Stacked N times.
  • PositionalEmbedding: Sinusoidal encoding added to projected input.
  • factor_weights: Dense(input_dim, activation='sigmoid') — weights input features before projection.
  • PredictionHead: Dense(d_model/2, relu) → Dense(output_dim, linear), output ×100.
  • Index_Model: create_sequences, prepare_data (80/10/10 train/val/test split), train_model with EarlyStopping + ReduceLROnPlateau + ModelCheckpoint.
  • ModelManager: save_weights / load_weights / save_model / load_full_model.
  • Status: Architecture only. No trained weights file exists in the repository. Never called from any running code path.

Factor_Management (Quant Models/Irrationality_Index/Factor_Management.py)

  • Opens/closes Refinitiv (LSEG) API session via refinitiv.data
  • Loads OHLC price (TR.CLOSE / TRDPRC_1), volume (TR.Volume / ACVOL_UNS), fixed income mid price/yield
  • Loads macro data (CPI, rates, etc.) from FRED via pandas_datareader
  • Status: Data loader only. No signal construction on top of raw data.

ArxivToolClient (Research_LLM/arxiv_client.py)

~1,079 lines. All 10 tool methods fully implemented. Rate limiting (3 s min interval), exponential-backoff retry on 429/503, path traversal protection, PDF text extraction via pypdf.

LLM Providers (Consulting Dashboard/backend/modules/llm/)

Three providers — ClaudeProvider, OllamaProvider, OpenRouterProvider — all streaming via SSE with temperature=0.3 default. Factory pattern in factory.py.

7. Honest Caveats

(a) Resume claims the code does not currently support

  • "Automated research pipeline": Every stage requires manual user action (select paper, ask question). There is no scheduler, trigger, or autonomous loop that goes paper→signal without human input.
  • "Integrating model outputs": The IrrationalityIndex model has no trained weights and is never called from any running code path. There are no model outputs to integrate.
  • "Volatility, credit spread, momentum, VWAP/EMA, signals filtered by VSN": None of these are computed in any file. Factor_Management.py loads raw data from Refinitiv; no signal construction sits on top of it. The resume appears to describe the intended design of the Irrationality_Index submodule, not the current state of the code.

(b) Stubbed / incomplete

  • Data_Analysis.py: 7-line comment listing planned tools (Sharpe, rolling return, MDD, Bayesian), no implementation
  • Data_Reformation.py, Data_Management.py, Index_Evaluation.py: 1-line empty files
  • Trading Analysis DL/: Only __init__.py stubs — zero implementation
  • Factor, Regime, Portfolio dashboard pages: "Coming Soon" UI only
  • IrrationalityIndex: Architecture defined, no trained model, no inference endpoint, not connected to dashboard

(c) Could not verify from available files

  • Whether any trained weights for IrrationalityIndex exist outside this repository (e.g., on Google Colab, based on the "Created using Colab" commit message)
  • Whether Factor_Management.py is actively connected to a live Refinitiv session anywhere — no calling script was found in the repo

Summary

Genuinely strong and defensible: The MCP server (mcp_server.py + arxiv_client.py, ~1,100 lines, fully functional, 23 unit tests), the two-level ChromaDB semantic search pipeline (abstract + section), and the LLM chat system with structured task-mode prompts.

Real but untrained: The IrrationalityIndex transformer architecture (Keras/TensorFlow, sigmoid feature-weighting gate, multi-head attention).

Not yet implemented: Signal computation, alpha extraction, backtesting, regime detection, portfolio tracking.
